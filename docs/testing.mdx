## Test Projects

- `integration`: Loader runtime, action RPC, auth bridge, meta, ACF, ability coverage, and route-caching coverage through the shared Astro fixture.
- `static-build`: Real `astro build` validation for static loader content collections.

The shared Astro fixture in `tests/fixtures/astro-site/` includes both:

- `src/content.config.ts` for build-time collections used by static loader coverage.
- `src/live.config.ts` for runtime collections used by `getLiveCollection()` and `getLiveEntry()` SSR coverage.

## Local Workflow

Start local WordPress first:

```bash
pnpm run wp:start
pnpm run wp:status
```

`wp-env` is configured with automatic port selection. If `8888` is unavailable, run `pnpm run wp:status` to see the active local WordPress URL and ports.

Run tests:

```bash
pnpm run test:integration
pnpm run test:build
# or run both projects
pnpm test
```

Stop or reset local WordPress:

```bash
pnpm run wp:stop
pnpm run wp:clean
```

## Auth Bridge Coverage

Auth bridge behavior is covered by the `integration` project against `wp-env`.

- Action integration tests call real `/_actions/*` endpoints from the shared fixture in `tests/fixtures/astro-site/`.
- `tests/setup/global-setup.ts` provisions auth fixtures (application password, JWT, cookie+nonce) before integration suites run.
- Live loader runtime tests call real Astro pages in the same fixture to verify `defineLiveCollection()` wiring, schema validation, and SSR rendering for posts, pages, categories, and CPT content.
- Route-caching tests build the same fixture with `@astrojs/node`, start the standalone server entry, and verify cache hints plus the packaged invalidation actions end to end.

## Runtime limits and isolation

The integration project and static-build project run sequentially under `pnpm test`. Each project has a portable 15-minute process deadline with a five-second termination grace period; CI jobs allow 20 minutes including WordPress startup and cleanup. On the current Linux development host, the integration project takes about 15–30 seconds and static-build takes about 50–60 seconds after WordPress is ready. These are local measurements, not CI runner performance guarantees.

Use `pnpm run test:integration -- --maxWorkers=1` for a low-resource run. Do not run multiple test commands against the same fixture and WordPress environment concurrently. WordPress startup executes the excluded PHP fixtures and seed script; Astro templates are covered by package-local ESLint/Prettier, Astro Check, and the real static/SSR builds.
